# 薄肌感男生修图 Skill

**Lean Muscle Photo Glow-Up**

## 目标与优先级

默认整体约 **20%**、手臂约 **15%** 的综合视觉增强；手臂在整体目标内采用较轻分配，百分比不是宽度、臂围或真实肌肉量增幅，不逐部位叠加。手臂优先通过三角肌与上臂、二头肌与三头肌交界处符合原光源和受力的柔和明暗过渡提升分离度与立体感，必要时少量增加饱满度；原有臂围足够时保留外轮廓。用户最新明确的整体或局部强度优先，不能把手臂回调误用为全身降至15%。

把**照片中的本人**修成更帅、更精神、肌肉更有训练感、具有自然生活摄影质感的健身网红形象。目标介于日常运动型与竞技健美之间：胸肩背臂及可见臀腿协调饱满、上下身比例协调、自然线条清楚，不用机械加围度、极低体脂或商业抹油感制造效果。

**默认比例目标是有运动员感、视觉显高的健体身形。** 通过肩腰差、腰胯与腿肌的量感关系、股四头肌外抛与膝部收束、小腿肌腹隆起与踝部渐细等对比建立比例，实际可见时配合自然人鱼线。显高不以绝对拉长腿、抬高裤腰或把四肢削细实现；具体形态与禁忌见肌肉参考第七、八节。

**优先级：用户本图明确范围与锁定项 > 本人辨识度、真实人体结构与摄影可信度 > 面部自然美化及健体表现的可见收益 > 风格化。** “自然”不等于不修脸、不增强肌肉；“增强”不等于每个肌群必须放大。**面部、皮肤、肌肉和原片成像的真实感必须写入首轮编辑指令，不留到返修补救。**

## 执行流程：五个必须完成的检查点

### 1. 确定输入与编辑范围

看见并确认本次输入图、对照版本、完整或局部任务、本图锁定项和可编辑工具。

- **新图**：“修一下/按 Skill 修图”默认完整评估；上一张临时限制不继承。
- **同图返修**：“只改某处、其他不动”仅处理指定目标与允许的必要联动，以该图认可版本为基准；不自动使用尚未认可的输出。
- **补充重点**：“胸再厚一点”提高该项优先级，不自动缩成局部修图，也不解除既有锁定。
- **批量/长期指令**：逐张判断；仅继承用户明确指定给整组或今后照片的规则。

**完成标准：** 明确输入、基准、要改什么和不能改什么；真正影响执行且无法确定时只问必要问题。未看到图片不可编造观察。

### 2. 看图后确定具体编辑目标

对可见且允许修改的区域，内部以 `当前状态 → 具体动作（方向/程度）→ 需要联动的部位 → 可观察的结果` 记录简短目标；看不到的区域标记不适用，不补画遮挡下的肌肉。避免空泛的“更帅”“更壮”“更自然”。

- **面部可见：** 根据本图自然减轻明显抬头纹、眉间纹、法令纹、眼周细纹、疲态和临时瑕疵；适度优化眉眼、面颊、下颌及发际线。保留身份、眼神、嘴角、微表情、真实皮纹、自然不对称和原发型。细节按面部参考执行。
- **肌肉可见：** 按肌肉参考的**体积、外轮廓、肌群比例、线条、光影**五维检查胸、三角肌前中后束、背、手臂、腰腹及画面中的下肢。肌肉偏薄或用户明确要增大，落实有方向的体积与轮廓变化；已有优势则可保留量感，重点提升曲面、衔接、自然分离、衣料及光影表现，避免机械放大。**保留优势体积≠用户锁死该部位，也≠完全不处理。**
- **摄影与衣物：** 记录原光源、白平衡、肤色、环境色饱和度、曝光、景深、颗粒、清晰度、衣料张力及背景。体积变化时让衣料随之自然撑起，保留材质、Logo、文字、缝线、动作、关节、镜面和透视；默认沿用原片氛围与自然色彩，不因健体塑形而连带增艳、提白肤色、套滤镜、强虚化或改成商业棚拍光。色彩细则见《面部与真实摄影标准》第三节。

**可见腿部与整体比例：** 不限于完整全身照；泳裤、短裤、抬腿或下肢部分遮挡的照片，也要检查实际可见的大腿、小腿与肩胸腰胯的量感关系。肩头偏平时补足肩部外缘圆弧和前后厚度；腿部按参考第七节分别确定股四头肌外抛、膝上收束、腰胯—腿肌关系、人鱼线和小腿肌腹—踝部的对比目标。不是每项都加粗；把当前缺少的形态、变化方向与可见结果写明。透视缩短、屈膝和遮挡不视为真实短腿，不为显高移动关节、抬高腰线或补画不可见部分。

当形体已接近理想、工具无法可靠局部增强、进一步形变失真风险更高，且真实摄影质感仍能带来健体表现收益时，才允许完整任务**基本不改形体**。不能未经说明把用户明确要求的增大降级成调色。

**完成标准：** 每个选定目标都有具体可见的动作和结果；用户锁定与需联动的结构不冲突；首轮方案同时含美化、表现收益与活人感保护。

### 3. 生成完整指令并执行一次编辑

确认工具确实能读取输入：支持局部编辑时优先定向处理；只有整图参考编辑时采用保守但具体的全图指令；能力有限则只承诺可实现范围。不要为评估工具等级额外生成试验图。

**首轮提示词必须包含以下六项（不适用的修改删除，适用的保护保留）：**

1. 输入基准、用户核心诉求、完整/局部范围及明确锁定项。
2. 各目标部位的**具体形状/方向/幅度/预期可见变化**，以及形体与衣料联动；适用时分别写出肩头饱满度，以及股四头肌外抛—膝部收束、腰胯—腿肌、小腿肌腹—踝部等比例对比，不能只写“轻微增强全身”或“大腿加粗”。优势部位写表现力目标，不能擅自写“全身肌肉大小不变”；不凭空设置统一的低幅度百分比上限，让明确的增大目标失效。
3. 自然面部美化：本图需要减轻的皱纹、疲态、轮廓或发际线；保留五官、眼神、微表情、细发丝、自然不对称和真实皮肤微纹理。
4. **真实肌肉与皮肤：** 原光源下的柔和曲面转折、自然哑光或场景允许的局部反光；不靠硬黑描线、过锐化、假油光、蜡感或人工腹肌。皮肤按原片可辨细节与肤色变化保留，不因塑形而重绘成均匀光滑表面；不以新增高清毛孔、毛发或噪点冒充原片质感。
5. **原片成像与自然色彩：** 以原始照片的光源、白平衡、肤色和环境固有色为基准，延续曝光特点、清晰度差异、细微颗粒和原景深；不因塑形顺带提高饱和度、鲜艳度、肤色亮度或局部对比。保留动作关节、构图、服装文字、背景与镜像逻辑；明显偏色按需局部纠正，用户另有风格要求时遵循其范围。
6. 输出原图画幅的**单张编辑成片**；用户要求裁剪时按其构图目标执行，保留评估所需的可见身体区域，不以裁剪代替塑形。不加拼图、说明文字或水印。

**完成标准：** 已向可用图片编辑工具提交包含所有适用动作及首次真实感约束的完整指令，并得到可查看的编辑结果；不是只输出一段建议或一份提示词。无可用工具时明确说明并提供可复制指令，不能声称修图完成。

### 4. 对照输入验收结果

在正常社媒观看尺度及放大细节下，对照输入基准逐项标记`达标 / 缺陷 / 无法判断 / 不适用`，不能以“图片生成成功”代替验收。发生裁剪或输出分辨率变化时，以相近的人物显示尺寸比较肩、胸、腰、腿，排除整个人被放大的影响。

| 验收项 | 必须看到的结果 |
| --- | --- |
| 本人和活人感 | 同一个人，神态未僵化；适用的明显额纹及疲态已自然改善，同时毛孔、微表情、真实发丝和皮肤色差仍可信；无数字人磨皮感 |
| 肌肉与比例 | 实际执行了本图选定的体积**或**表现力增强；明确增大处确有合理轮廓变化；优势部位曲面、衔接、线条或撑衣表现改善；关节连接与上下身协调 |
| 手臂自然度 | 约15%的较轻视觉增强体现为自然分离度和必要的少量饱满度；原臂围充足可保持轮廓。肩臂、二三头肌交界过渡柔和，放松和发力有区别，无过粗上臂、黑色沟线、球状肩或脱水质感；不能以必须增粗作为通过条件 |
| 摄影与衣料 | 肤色、人物、服装、背景的光线及质地一致；无异常油光、背景拉扯、镜像错误、假虚化、Logo/文字损坏 |
| 自然色彩 | 对照原片分别检查肤色、衣物和大面积环境色：无新增偏橙、偏红、偏粉、漂白、过饱和或强局部对比，肌肉阴影保留自然色温；没有为降饱和使肤色发灰。形体改善不能替代本项通过 |
| 肩部与可见腿部 | 选定的肩部目标有外缘圆弧、前后厚度或自然肩臂过渡的变化；选定的腿部目标有大腿厚度、外侧弧线、膝上收束或小腿曲面的变化；分别检查，不能用胸腹改善代替。屈膝、透视、遮挡及衣物边缘可信 |
| 健体比例与显高 | 对应本图的肌腹与关节、腰胯与腿肌对比更清楚；外抛与收束连续，运动感增强而非整腿等宽增粗或削细。人鱼线只在可见区域自然呈现；不靠拉长肢体、移动腰线或改变衣物覆盖伪造结果。遮挡区域标记无法判断或不适用 |
| 范围与版本 | 未改动锁定区域；结果对应本次输入或认可版本；局部返修未重做已满意部分 |

完整健体任务若只有裁剪、调色、对比度或锐化变化而没有实际肌肉表现收益，判**缺陷**；只因总体围度没增加不能判失败。用户明确要求的肩部饱满、腿部增肌或比例改善没有对应可见变化，即使其他部位改善也判该项**缺陷**。无从验证的项目不得写成达标。

### 5. 必要返修并交付

仅对缺陷生成**具体的局部修复指令**，保留已通过及用户认可的部分；默认首轮后最多再做一次针对性返修，用户主动要求继续则按新指令。若失败、工具能力不足或无法保持身份和结构，停止并如实说明未达成项，不循环整图碰运气。

用户认可形体但指出肤质或颜色不自然时，分别记录认可与缺陷的范围。形体沿用认可版本；肤质与色彩回看原始照片，不把此前生成图的增艳、偏色或磨皮当成新的自然基准。仅返修有问题的维度，不重做已认可的肌肉形态。

**完成标准：** 达标则交付实际成片并保留原图与认可版本；未达标则交付可用最佳版本并明确局限，不宣称全部完成。批量逐张执行，保持风格一致。仅在用户明确要求时同步 GitHub，绝不自动公开私人照片。

## 使用边界

快速修图可隐藏内部判断并直接出片；互动模式可简短解释方案。两者**不省略五个检查点**，不强制用户逐项确认。专业参考按需读取、复用，缺失时说明而不是静默退化。部署需保留本文件及上述参考文件的相对路径。未经实际图片测试，不得把静态检查描述为实测成功。
